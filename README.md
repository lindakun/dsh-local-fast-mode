# DSH 快速模式：缓解 DeepSeek V4.1 Flash 1017 过度思考

**本插件专门为缓解 DSH 使用 `deepseek-v4.1-flash-1017` 时出现的“雷霆思考”或过度思考现象而制作。**
典型表现是：一个简单问题，本来只需查看一次配置，却不断扩大搜索范围、反复确认、
连续调用几十次工具，迟迟不给出答案。
另一个表现是创作任务在首次写文件之前生成数万 token 的内部思考，随后反复推翻同一实现。

本插件通过限制简单查询范围、明确停止条件、在回合中注入收尾提醒，帮助模型尽快回答。
它是独立的 DSH bundle，通过 `dsh.bundle.patch` 声明“快速模式”（`fast`）预设，
不修改应用包、内置代码或模型本身。

## 针对的问题与适用范围

- 主要目标：DSH + `deepseek-v4.1-flash-1017` 的简单问答出现过度调查、重复验证和工具调用迟迟不收尾。
- 1.1 版本同时针对页面、SVG 动画等创作任务在首次落盘前长时间规划、重复设计却只检查环境的现象。
- 1.2 版本进一步强调复杂创作分阶段实现、复用验收清单、根据失败证据修复，以及验收通过后的停止条件。
- 本次验证通过 WorkBuddy 国际版接入；日志记录的模型 ID 为 `deepseek-v4.1-flash`，供应商目录描述标注为 V4.1-Flash-1017。
- “雷霆思考”是这里对上述体验的俗称，并不表示已定位模型内部推理机制的缺陷。
- 插件优化的是 DSH 中的提示词与执行节奏，不能保证消除所有过度思考，也没有针对其他模型或接入渠道完成相同验证。

## 行为

- 简单状态查询默认只涉及当前 DSH 会话，目标一批工具调用，最多补查一批。
- 证据足够后立即回答，不自动盘点其他客户端或扫描应用归档。
- 复杂开发、明确要求的全面调查不受上述简单查询目标限制。
- 思考强度只在请求未指定时补 `low`，保留会话显式选择。
- 可选的请求输出预算仅在配置 `maxTokens` 时填入，显式指定的较小或较大预算均保留；默认不设置。
- 首步注入执行提醒：简短规划，先写最小可运行版本，再根据实际失败迭代；已有文件仍须先读取。
- 第三步开始每两步通过 `agent/pre-step` 注入一次收尾提醒，新用户输入重置计数。
- 查询批次规则是提示词约束，不是强制步数上限。
- 视觉检查、发现质量问题后的反复调整属于正常验证，不按工具次数认定为浪费，也不设置默认工具步数上限。
- 复杂创作先实现核心场景与主要交互，再补齐所有明确要求；最小版本只作为中间步骤。
- 验收清单通过后交付，不追加可选美化；同一问题连续两次修改未改善时先取证重新定位，不盲调，也不放弃必需修复。
- 检查命令链和页面实际结果，避免后续命令成功掩盖前序失败；截图生成不能替代初始化、异常和交互验证。

当前使用的 WorkBuddy `deepseek-v4.1-flash` 不支持 `off`，因此保留默认 `low`。
支持 `off` 的其他模型可以使用界面提供的档位；本插件不覆盖该选择。

### 输出预算的边界

`maxTokens` 是单次模型请求的输出上限，不是独立的思考 token 上限，也不是耗时或整回合上限。
实际计数与执行由供应商决定；不能把请求中出现该参数等同于通道一定执行了限制。
本次 WorkBuddy 实测中，请求设置为 16,384 后仍出现单步 18,297 和 19,807 输出 token，
因此撤回默认启用，不将它当作该通道可靠的思考或输出限制。
预算过小可能截断思考、回答或工具参数，导致任务未完成；插件不会静默无限重试。
需要长输出的任务可以显式提高预算或切换其他预设。

如已验证自己的通道支持，可在本插件 `cordis.patch.yml` 的 `fast-tuning.config` 下
添加 `maxTokens`，必须为正整数。该选项不会覆盖会话显式指定的预算。
简短规划约 500 token 和先落盘要求属于提示词目标，不能保证模型每次遵守。

## 文件

- `cordis.patch.yml`：预设声明、工具组成和 persona，作为配置的唯一来源。
- `fast-tuning.mjs`：通过 Cordis 的 `agent/request` 接口补充缺省档位与输出预算，按步骤注入执行和收尾提醒。
- `fast-tuning.test.mjs`：验证用户选择、输出预算、默认值、预设隔离、错误传播与回合提醒。
- `verification.json`：本次原始问题的前后实测统计，不包含原始会话内容。
- `verification-creative.json`：动画任务的完整基线与未通过验收的候选实验，保留输出预算未生效的证据。

运行 `npm test` 验证中间件。

### 创作任务的后续发现

同一模型的一次完整 SVG 动画任务用了 750.645 秒、27 个模型步骤、26 次工具调用，
首次写入调用发生在 470.336 秒。前两步只检查目录和浏览器，却输出了 51,177 token，
这是本轮优化优先针对的等待阶段。后续看图、修复结构与运动问题不能仅因次数多被判为过度思考。

“执行提醒 + 16,384 请求输出预算”的候选实验在约 305 秒首次写出文件，
但仍发生长思考，且两次单步输出超过声明预算，因此没有通过“可靠限制长思考”的验收。
该实验由测试人员停止，不能把它当成完整任务完成耗时的提升证明。
最终版本保留先落盘和聚焦目标的提醒，撤回默认输出预算，不默认限制工具步骤，
并保留完整视觉迭代能力。当前通道的单次长思考问题尚未获得可靠的硬限制方案。

最终配置另用一个限 60 行的最小 SVG 圆点动画验证：9.508 秒首次写入，14.813 秒完成，
脚本语法检查通过。这个轻量检查只证明插件加载和基本执行正常，不能替代完整动画任务的性能或质量验证。

### 1.2 版本的改进依据与验证边界

2026-10-25 检查的一条 Three.js 海岸骑行会话已加载 1.1 版本规则和执行提醒，
但首次写入仍发生在约 167 秒，第 3 步模型请求耗时约 154 秒、输出 38,713 token，
一次写出约 66,387 字符的页面。输出计数包含思考、正文和工具参数，不能全部算作思考 token。
读取时的日志快照覆盖约 18 分 30 秒，已有 82 次工具调用和 41 次提醒，尚无回合结束记录。
后续既有围巾、镜头等反复调整，也有抓鱼判定等有效修复，不能把全部耗时视为浪费。

1.2 据此增加分阶段实现、具体完成条件、重复修复先取证、识别命令与页面失败的规则，
并在动态提醒中复述关键执行条件。提醒频率、工具权限和默认输出预算保持原有行为。
这些仍是提示词约束，不能中断正在进行的单步长生成，也不能从中间件自动判断画面是否合格。
本次以现有中间件测试验证兼容性，尚未完成新版本的完整 Three.js 同题复测，
因此不宣称创作速度或质量已经改善。上方历史实测数据不代表 1.2 版本的性能结果。

## 安装与更新

推荐先克隆仓库，方便后续用 Git 更新：

```bash
git clone https://github.com/lindakun/dsh-local-fast-mode.git
cd dsh-local-fast-mode
npm test
pwd
```

在 DSH 的插件管理器中添加 `link:<上一步输出的绝对路径>`，安装后新建会话并选择“快速模式”。
也可以在支持 GitHub 安装源的插件管理器中使用 `github:lindakun/dsh-local-fast-mode`；
本次实测采用本地 `link:` 安装方式。
插件须同时出现在 profile 的 `dependencies` 与 `dsh.profile.bundles` 中。
若已有内嵌的同名 `fast` 声明，先备份并移除旧声明，避免重复预设 ID。

如果桌面内置 pnpm 与已有依赖使用的 pnpm 主版本不同，可能遇到
`ERR_PNPM_UNEXPECTED_STORE`。本次安装使用与现有依赖一致的 pnpm 版本添加本地链接，
再在 profile 的 bundle 列表注册；不要为安装此插件随意切换全局 store 或升级其他插件。

本地链接安装后的更新方式：

```bash
cd <插件克隆目录>
git pull --ff-only
npm test
```

测试通过后重启 DSH，新建“快速模式”会话验证。GitHub 直接安装的副本请使用
当前 DSH 版本支持的插件更新流程；仓库推送不会自动改写已安装副本。

普通应用更新不会直接改写本目录的源码；链接与 bundle 注册均保存在用户 profile。
本地目录需要持续保留，删除、移动或重建 profile 后需要重新添加链接。
建议把克隆目录放在固定的插件目录，例如 `~/.dsh/local-plugins/dsh-local-fast-mode`，
不要放在经常清空的作品工作区内；`link:` 不会复制源码，源目录被删后插件也会失效。
DSH 仍处于预览期，升级可能改变 Cordis 接口或预设配置格式；升级后需运行测试、
重启应用并新建快速模式会话验证。此机制避免应用文件覆盖，不保证跨版本接口永远兼容。
已有会话可能继续使用创建时的预设快照，验证配置变更应新建会话。

## 回滚

安装前请自行备份 desktop profile。首次迁移的完整回滚需在退出 DSH 后恢复备份中的 `cordis.patch.yml`、`package.json`、
`pnpm-lock.yaml` 与 `fast-tuning.mjs`，再启动应用。恢复整份 profile 会撤回备份之后的其他设置，
因此有后续配置改动时应只针对本插件移除依赖、bundle 条目并恢复旧预设声明。

后续仅回滚本插件版本可使用 Git，再重启 DSH、新建会话验证。
源码仓库不保存账号、凭据、完整 profile 或原始会话。
