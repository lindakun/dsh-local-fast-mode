# DSH 快速模式：先给结论，深入取证由用户决定

独立的 DSH bundle，当前版本 **1.7.0**。主要针对简单任务不断补证据、迟迟不回答的体验。
本版使用简短通用提示和执行预算，不绑定设备、协议、目录或具体业务。
不修改 DSH 安装包、内置代码或已有 profile；继续由用户 profile 的本地 `link:` 加载。

## 两种模式

| 预设 | 用途 | 行为 |
| --- | --- | --- |
| 快速模式（`fast`） | 先取得必要材料，交付已确认结论和疑点 | 有限取证，未知项等待用户决定是否继续 |
| 完整执行（`fast-full`） | 用户明确选择的深入调查、开发或完整验证 | 不使用快速取证预算，完成所要求的必要工作 |

快速模式在用户未明确授权时使用预算；收到真实用户对当前工作的明确继续、深入或执行授权后，
自动解除取证批次和工具次数限制，无需切换预设。完整执行预设仍作为显式选择保留。
DSH 已开始的会话可能不允许切换预设，但不影响快速模式中的自动授权处理。

### 授权如何生效

- 直接指令例如“请深入排查”“开始实施”“帮我修复这个问题”“继续”，可自动解除当前工作的两项预算。
- 在明确询问是否继续，或预算结束等待确认后，回复“好”“可以”“同意”“yes”等可解除预算；没有待确认上下文的普通肯定答复不视为授权。
- 当前工作已授权时，简短继续或进度询问继承授权；新的独立请求重新判断，避免把一次授权扩大为整个会话的无限预算。
- “恢复预算限制”“不要继续深入”等可恢复限制。普通分析、方案讨论、否定指令、引用与代码块不作为授权；工具通知和模型自述也不能授权。
- 判定使用本地确定性规则，不增加模型调用。支持上述直接表达和部分中英文等价表达，不是任意自然语言的完整语义解析；含义不明确时保留预算，用户可用明确继续或执行指令消除歧义。
- 授权在回合结束后保留相同任务的续问语义，恢复会话时从本会话的真实用户输入与确认问题重建。不读取其他会话，也不解除 DSH 本身的权限、审批或取消约束。


## 快速模式的默认预算

| 配置项 | 默认值 | 含义 |
| --- | ---: | --- |
| `maxToolRounds` | 10 | 未授权时最多十个模型提出工具调用的批次，同批多个调用只占一个批次 |
| `maxToolCalls` | 20 | 未授权时最多二十次执行准入，同批并发和失败尝试也计数 |
| `toolTimeoutMs` | 15000 | 每次已准入工具执行在十五秒后发出独立取消信号 |

这些值是保守的初始保护参数，不是性能最优值，也不是必须用完的目标。
首步要求优先取得核心材料并尽早回答；材料不足时收窄结论、标出缺口，
不能为了证明唯一原因、消除所有未知或完善报告递归调查。

未授权时达到任一预算，或单次工具执行超时后，下一次模型请求移除工具，只保留一次回答机会，
要求输出已确认结论、关键依据、未知疑点和必要建议。执行 guard 同时拒绝额外操作。
不存在的工具请求也消耗批次，不能通过反复错误重试绕过上限。
模型同批提出的请求数可能超过二十个；超出准入预算的请求返回拒绝结果，不执行工具本体。

若异常模型在无工具阶段仍请求工具，不再循环重试：插件停止该回合，
给出明确的预算与回答失败说明，不编造已经完成的结论。DSH 会将该异常兜底回合标为 blocked。
用户取消和上游错误保持原有语义。

## 提示与执行边界

- 默认先返回已确认结论，未确定事项列为疑点；继续深入取证需要用户决定。
- 准确性通过限定结论实现，不把“不确定”自动变成继续调查的理由。
- 只在首步和强制回答阶段注入简短提示，不再逐步追加核查清单；用户请求摘录最多 600 字符。
- 通过公开 `agentPresets.composedPreset` 判断当前预设，创建 header 不作为切换后的依据。
- 提示组装通过公开 `system-prompt/assemble` 移除工具，正常进入 DSH 的持久化请求记录；不在供应商出口静默改写。
- 执行 guard 提供单调拒绝，其他策略不能把预算拒绝重新改成允许。
- 两种预设均允许显式后台命令，启动操作按普通调用计入快速预算；成功返回作业信息后，后台任务的运行时长不受本插件十五秒执行等待限制。
- 两种预设仍关闭命令超时后自动转后台；需要后台运行时应明确使用后台启动，而不是依赖前台超时自动提升。
- 单次工具取消需实现响应 AbortSignal，实际返回还包含取消清理时间。已验证 DSH 本机 Shell 会结束前台任务；不响应取消的第三方工具不能保证按时结束。
- 批次限制不能计算 Shell 字符串内部执行了多少条命令，也不能完全阻止命令自行派生、脱离控制的进程。
- 预算不限制供应商的单步思考时长或回答时长，不能承诺整回合在固定秒数内完成。

完整执行保留实现与验证能力，但仍要求只做用户范围内的工作，不声明未验证的结果。
两项取证预算只对未明确授权的工作生效。授权后不再因批次或调用次数转入强制回答；
快速模式的单次工具十五秒取消仍保持，且超时不强制结束已授权工作。完整执行不使用该快速取消计时。

### 其他工具与上下文配置

两种预设复用的文件搜索配置为：最多展示 60 个文件路径、120 个匹配，搜索超时 15 秒。
网络搜索自身超时为 20 秒；快速模式另有外层单次工具 15 秒取消。
工作区指令加载的 `maxBytes` 为 65,536；长工具结果的上下文裁剪阈值为 4,096 字符，
保留头部 2,048 和尾部 512 字符。这些展示或上下文上限不等于修改文件或终止后台任务。
默认仅在用户未选择思考档位时补 `low`，不强制覆盖显式选择，默认不设输出 token 上限。
上述均为本插件配置；DSH 自身的权限、工具默认参数与生命周期行为仍由 DSH 管理。

## 参数与输出预算

在 `cordis.patch.yml` 的 `fast-tuning.config` 中可设置上述正整数；
中间件还支持 `preset`、`fullPreset`（两者必须不同）、`reasoningEffort` 和可选 `maxTokens`。
两种预设通过 YAML anchor 复用同一工具组成，不复制两套规则。
修改后运行检查、重启 DSH，再创建新会话验证。

思考档位只在请求未指定时补 `low`，保留用户显式选择。默认不设置 `maxTokens`。
它是单次请求输出预算，不能当作独立思考预算或整回合耗时限制；
此前 WorkBuddy 通道曾返回超过请求声明的输出计数，因此没有重新默认启用。

## 验证与复现

```bash
npm test
npm run test:integration
```

当前 27 项单元测试覆盖授权语句与上下文、引用和否定、预算、并发、预设切换、回合重置、超时和异常兜底。
`test:integration` 需要本机已安装 `dsh`；它使用临时 DSH_HOME、确定性模型适配器和模拟工具，
在真实 DSH 提示组装及工具调度中验证执行上限、无工具回答、取消、授权续查与完整执行。
不连接模型供应商或业务设备，也不修改现有 profile。

本次十三项真实流水线检查通过，包括默认十批取证后第十一次请求无工具回答、并发准入上限、
未知工具重试、工具取消、后台启动、完整执行、直接授权和引用隔离。
另以独立进程恢复同一会话验证：先在一批测试预算后回答，用户回复“好”后，
实际执行六批工具仍不受一批上限限制；用户再恢复预算，实际执行又回到一批后回答。
异常最终调用仍提供明确失败说明，不递归重试。

`verification-budget.json` 保存集成结果；`verification-budget-model.json` 保存 WorkBuddy 模型的隔离抽查。
后者使用固定模拟证据和预设服务替身，不代替桌面 GUI、真实任务或其他供应商的端到端验证。
模拟耗时不代表生产耗时，不能根据有限样本保证所有任务均更快。
1.6 版本真实模型的两次抽查使用两批、三次准入的小预算：普通请求在两步约 7.8 秒回答，
持续追查请求在三步约 10.1 秒回答。该结果只证明本次取证与回答路径正常，
不构成默认预算的生产性能或全面事实准确性证明。

历史记录 `verification.json`、`verification-creative.json`、`verification-scope.json`
保留旧版的收益与失败证据，不代表本版性能。未发布的 1.5 候选曾增加证据核查规则，
但真实会话出现 28 个模型步骤、44 次工具调用，约 336 秒后仍未交付；
本版以预算与先交付策略替代该候选，不把它作为成功版本发布。

## 安装与更新

推荐先克隆仓库，方便后续用 Git 更新：

```bash
git clone https://github.com/lindakun/dsh-local-fast-mode.git
cd dsh-local-fast-mode
npm test
pwd
```

在 DSH 的插件管理器中添加 `link:<上一步输出的绝对路径>`，安装后新建会话并选择“快速模式”。
也可以在支持 GitHub 安装源的插件管理器中使用 `github:lindakun/dsh-local-fast-mode`；
本次实测采用本地 `link:` 安装方式。
插件须同时出现在 profile 的 `dependencies` 与 `dsh.profile.bundles` 中。
若已有内嵌的同名 `fast` 声明，先备份并移除旧声明，避免重复预设 ID。

如果桌面内置 pnpm 与已有依赖使用的 pnpm 主版本不同，可能遇到
`ERR_PNPM_UNEXPECTED_STORE`。本次安装使用与现有依赖一致的 pnpm 版本添加本地链接，
再在 profile 的 bundle 列表注册；不要为安装此插件随意切换全局 store 或升级其他插件。

本地链接安装后的更新方式：

```bash
cd <插件克隆目录>
git pull --ff-only
npm test
```

测试通过后重启 DSH，新建“快速模式”会话验证。GitHub 直接安装的副本请使用
当前 DSH 版本支持的插件更新流程；仓库推送不会自动改写已安装副本。

普通应用更新不会直接改写本目录的源码；链接与 bundle 注册均保存在用户 profile。
本地目录需要持续保留，删除、移动或重建 profile 后需要重新添加链接。
建议把克隆目录放在固定的插件目录，例如 `~/.dsh/local-plugins/dsh-local-fast-mode`，
不要放在经常清空的作品工作区内；`link:` 不会复制源码，源目录被删后插件也会失效。
DSH 仍处于预览期，升级可能改变 Cordis 接口或预设配置格式；升级后需运行测试、
重启应用并新建快速模式会话验证。此机制避免应用文件覆盖，不保证跨版本接口永远兼容。
1.3 依赖公开的 `agentPresets` 服务及 `composedPreset` 方法；升级后还应在空白会话中
从其他预设切入快速模式，确认首步提醒出现。服务依赖缺失由 Cordis 加载诊断显示，
不会退回读取可能过期的创建 header。
1.6 还依赖公开的 `system-prompt/assemble`、`tools.guard` 与工具取消接口；
升级后运行集成检查，确认工具移除、执行拒绝和回答阶段仍按预期工作。
已有会话可能继续使用创建时的预设快照，验证配置变更应新建会话。

## 回滚

安装前请自行备份 desktop profile。首次迁移的完整回滚需在退出 DSH 后恢复备份中的 `cordis.patch.yml`、`package.json`、
`pnpm-lock.yaml` 与 `fast-tuning.mjs`，再启动应用。恢复整份 profile 会撤回备份之后的其他设置，
因此有后续配置改动时应只针对本插件移除依赖、bundle 条目并恢复旧预设声明。

后续仅回滚本插件版本可使用 Git，再重启 DSH、新建会话验证。
源码仓库不保存账号、凭据、完整 profile 或原始会话。
