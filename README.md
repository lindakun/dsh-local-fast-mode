# DSH 快速模式：先给结论，深入取证由用户决定

独立的 DSH bundle，当前版本 **2.0.0**。主要针对简单任务不断补证据、迟迟不回答的体验。
本版使用简短通用提示和执行预算，不绑定设备、协议、目录或具体业务。
不修改 DSH 安装包、内置代码或已有 profile；继续由用户 profile 的本地 `link:` 加载。

## 两种模式

| 预设 | 用途 | 行为 |
| --- | --- | --- |
| 快速模式（`fast`） | 先取得必要材料，交付已确认结论和疑点 | 有限取证，未知项等待用户决定是否继续 |
| 完整执行（`fast-full`） | 用户明确选择的深入调查、开发或完整验证 | 不使用快速取证预算，完成所要求的必要工作 |

快速模式在用户未明确授权时使用预算；收到真实用户对当前工作的明确继续、深入或执行授权后，
自动解除取证批次和工具次数限制，无需切换预设。完整执行预设仍作为显式选择保留。
DSH 已开始的会话可能不允许切换预设，但不影响快速模式中的自动授权处理。

### 授权如何生效

- 直接指令例如“请深入排查”“开始实施”“帮我修复这个问题”“继续”，可自动解除当前工作的两项预算。
- 在明确询问是否继续，或预算结束等待确认后，回复“好”“可以”“同意”“yes”等可解除预算；没有待确认上下文的普通肯定答复不视为授权。
- 当前工作已授权时，简短继续或进度询问继承授权；新的独立请求重新判断，避免把一次授权扩大为整个会话的无限预算。
- “恢复预算限制”“不要继续深入”等可恢复限制。普通分析、方案讨论、否定指令、引用与代码块不作为授权；工具通知和模型自述也不能授权。
- 判定使用本地确定性规则，不增加模型调用。支持上述直接表达和部分中英文等价表达，不是任意自然语言的完整语义解析；含义不明确时保留预算，用户可用明确继续或执行指令消除歧义。
- 授权在回合结束后保留相同任务的续问语义，恢复会话时从本会话的真实用户输入与确认问题重建。不读取其他会话，也不解除 DSH 本身的权限、审批或取消约束。
- “同意授权”“批准”“确认授权”等表达同样视为授权；只有明确要求恢复限制才撤销，无法识别的普通消息保留原有状态，不会因为一句话不匹配就重新上锁。

### 预算耗尽时的选择框

预算耗尽时，除文字确认外还会在支持提问的客户端弹出一次选择框。窗口是**限时阻塞**的（默认 `authorizePromptTimeoutMs` 为 10000 毫秒）：

- 快捷选项为“继续深入”和“就此交付”。选“继续深入”立即解除本次工作的两项预算并在同一回合继续；选“就此交付”停止工具、只输出已确认结论和未确认疑点。
- **始终保留自由输入**：用户不必二选一，可在输入框写明自己的安排（例如“先修 A，再跑测试”）。输入的原文会原样写入会话事件并进入后续模型上下文，不被裁剪或替换成固定文案；授权判断仍只看这份文本的语义，识别为授权才解除预算，否则按交付处理。选择快捷选项时附带的自由输入同样保留，快捷选项本身决定授权状态。
- 选择结果与原文分开保存：`source.kind = fast-mode-budget`、`form = authorization-choice`、`choice = grant|decline` 记录授权决定，消息正文保存用户原文；恢复会话时按 `choice` 重放，不需要重新做文本匹配。超时默认值不落盘，恢复会话后不会凭空多出一次授权。
- **超时无人应答按“继续深入”处理**：等待满十秒仍没有任何响应，视为用户已离开位置，自动解除本次工作的两项预算并继续调查，不再阻塞回合。该决定只存在于本回合内存中，不写入会话事件、不标记为显式授权，因此下一个独立请求仍重新受预算保护。
- 每个预算周期只弹一次。没有提问服务（headless、CLI、脚本调用）时不会弹框，自动退回原有文字路径，行为与本版之前一致；该路径可作为手工输入兜底。
- 等待期间使用独立超时并转发回合取消信号。用户主动取消回合、服务报错或没有应答者时仍退回强制回答，不虚构用户选择；只有“窗口开着且完全没响应”才走默认继续。
- 弹窗是可选的增强项，可用 `authorizePrompt: false` 关闭，关闭后完全退回文字识别。
- 该能力全部由本插件通过公开的 `ctx.userQuestions.ask` 提供，不修改 DSH 源码；DSH 升级后若服务缺失，插件仍能正常加载并保持文字路径。


## 快速模式的默认预算

| 配置项 | 默认值 | 含义 |
| --- | ---: | --- |
| `maxToolRounds` | 10 | 未授权时最多十个模型提出工具调用的批次，同批多个调用只占一个批次 |
| `maxToolCalls` | 20 | 未授权时最多二十次执行准入，同批并发和失败尝试也计数 |
| `toolTimeoutMs` | 30000 | 每次已准入工具执行在三十秒后发出独立取消信号，并把该上限写进结果正文 |
| `authorizePrompt` | true | 预算耗尽时是否弹出授权选择框；关闭后退回纯文字识别 |
| `authorizePromptTimeoutMs` | 10000 | 选择框的最长阻塞等待时间；超时无响应按继续深入处理 |

这些值是保守的初始保护参数，不是性能最优值，也不是必须用完的目标。
首步要求优先取得核心材料并尽早回答；材料不足时收窄结论、标出缺口，
不能为了证明唯一原因、消除所有未知或完善报告递归调查。

未授权时达到任一预算，或单次工具执行超时后，下一次模型请求移除工具，只保留一次回答机会，
要求输出已确认结论、关键依据、未知疑点和必要建议。执行 guard 同时拒绝额外操作。
不存在的工具请求也消耗批次，不能通过反复错误重试绕过上限。
模型同批提出的请求数可能超过二十个；超出准入预算的请求返回拒绝结果，不执行工具本体。

若异常模型在无工具阶段仍请求工具，不再循环重试：插件停止该回合，
给出明确的预算与回答失败说明，不编造已经完成的结论。DSH 会将该异常兜底回合标为 blocked。
用户取消和上游错误保持原有语义。

## 提示与执行边界

- 默认先返回已确认结论，未确定事项列为疑点；继续深入取证需要用户决定。
- 准确性通过限定结论实现，不把“不确定”自动变成继续调查的理由。
- 只在首步和强制回答阶段注入简短提示，不再逐步追加核查清单；用户请求摘录最多 600 字符。
- 通过公开 `agentPresets.composedPreset` 判断当前预设，创建 header 不作为切换后的依据。
- 提示组装通过公开 `system-prompt/assemble` 移除工具，正常进入 DSH 的持久化请求记录；不在供应商出口静默改写。
- 执行 guard 提供单调拒绝，其他策略不能把预算拒绝重新改成允许。
- 两种预设均允许显式后台命令，启动操作按普通调用计入快速预算；成功返回作业信息后，后台任务的运行时长不受本插件三十秒执行等待限制。
- 两种预设仍关闭命令超时后自动转后台；需要后台运行时应明确使用后台启动，而不是依赖前台超时自动提升。
- 单次工具取消需实现响应 AbortSignal，实际返回还包含取消清理时间。已验证 DSH 本机 Shell 会结束前台任务；不响应取消的第三方工具不能保证按时结束。
- **取消原因不进命令输出，因此上限由插件写进结果正文。** DSH 在工具已开始执行后被取消时，会把成功结果替换成固定的 `Error: tool call aborted`，且不渲染取消原因；模型只看这句话，既看不到「超时」，也看不到三十秒，会继续下发同样超时的命令。插件因此在 `tools/post-execute` 把被自己计时器截断的调用改写为 `Error: <工具> command timed out after <ms>ms`，并注明这是快速模式上限、调大 `timeoutMs` 或 `--max-time` 无效、重发应压到约二十五秒内。成功结果、工具自身抛出的错误、用户主动取消都不会被改写（它们不带本插件登记的上限）。
- 批次限制不能计算 Shell 字符串内部执行了多少条命令，也不能完全阻止命令自行派生、脱离控制的进程。
- 预算不限制供应商的单步思考时长或回答时长，不能承诺整回合在固定秒数内完成。

完整执行保留实现与验证能力，但仍要求只做用户范围内的工作，不声明未验证的结果。
两项取证预算只对未明确授权的工作生效。授权后不再因批次或调用次数转入强制回答；
快速模式的单次工具三十秒取消仍保持，且超时不强制结束已授权工作。完整执行不使用该快速取消计时。

**超时与预算分别表述。** 单次工具超时和批次/次数用尽都会让本轮转入强制回答，但它们是两个原因，
提示文案、选择框标题与执行 guard 的拒绝理由都按真实原因分开写：超时说「单次工具执行超时」，
不再复用「取证预算已用尽」。同时满足时按超时表述，因为它更具体、也更能指导下一步动作
（缩短命令，而不是等用户加预算）。

### 其他工具与上下文配置

两种预设复用的文件搜索配置为：最多展示 60 个文件路径、120 个匹配，搜索超时 15 秒。
网络搜索自身超时为 20 秒；快速模式另有外层单次工具 30 秒取消。
工作区指令加载的 `maxBytes` 为 65,536；长工具结果的上下文裁剪阈值为 4,096 字符，
保留头部 2,048 和尾部 512 字符。这些展示或上下文上限不等于修改文件或终止后台任务。
快速模式**不降思考档位**：`high`、`max` 等显式选择原样保留，只在请求未带档位时补 `reasoningEffort`。
空转改由两项约束处理：`maxOutputTokens` 收窄单步输出预算，以及 persona 要求「不在推理里写产物正文、先落盘再迭代」。
完整执行模式不设输出上限，避免把必要的长输出截断。
上述均为本插件配置；DSH 自身的权限、工具默认参数与生命周期行为仍由 DSH 管理。

## 参数与输出预算

在 `cordis.patch.yml` 的 `fast-tuning.config` 中可设置上述正整数；
中间件还支持 `preset`、`fullPreset`（两者必须不同）、`reasoningEffort`、可选 `maxTokens` 与可选 `maxOutputTokens`。
两种预设通过 YAML anchor 复用同一工具组成，不复制两套规则。
修改后运行检查、重启 DSH，再创建新会话验证。

思考档位只在请求未指定时补 `reasoningEffort`（默认 `low`），**不覆盖** `high` 等显式选择；
这是刻意的取舍：降档能省时间，但会改变用户选定的推理深度，因此本插件改用输出预算约束体量。
`maxOutputTokens` 只在能收窄时生效（已声明更小的 `maxTokens` 则保留），且仅作用于快速模式。
当前默认 `16000`；`maxTokens` 仍默认不设，因为它只是补缺省值、不构成上限。
两者都是单次请求输出预算，不能当作独立思考预算或整回合耗时限制；
此前 WorkBuddy 通道曾返回超过请求声明的输出计数，实际压制效果需按会话日志的 `usage.outputTokens` 核对。

### 空转提示：重复取证才提醒，从不拦工具

`maxOutputTokens` 只是声明上限，实测中模型仍可写出数倍于该值的推理，并反复探测环境。
早期版本用过「连续 N 批没有落盘就只放行 write/edit」的硬闸门（`writeGateRounds`），
现已**移除**：它用“有没有写过文件”代理“模型是否在空转”，而快速模式的主力场景是排查/分析，
本来就没有磁盘产物，因此必然误杀（实测拦断了「列技能」和「扫描音箱日志」两轮会话），
而写一个一次性脚本就能解锁，对真正的空转又几乎没有约束力。

现在的做法是 `stallRounds`（默认 `3`，设为 `0` 关闭）：

- **判据是信息增益**：连续 `stallRounds` 批 `tool/result` 的正文签名（前 512 字符的 SHA-1）
  与上一批相同，即视为没有新信息。重复跑同一条命令、空结果才会命中。
- **只提示、不拒绝**：命中后追加一条 notice，说明「产出型任务先落盘；排查型任务忽略本条」，
  工具照旧全部可用。误判的代价是多一句话，而不是逼模型造一个无用文件来解锁。同一回合只提示一次。
- 排查/分析任务每批都拿到新日志或新状态，签名必然变化，**永远不会命中**。
- 用户明确授权后、完整执行模式下不提示；每个新用户请求重置连击计数。
- 与预算、超时是三套独立机制，提示文案不会冒充预算用尽或工具超时。

以上判据都是**启发式**：结果完全相同的两次调用仍可能是必要取证（例如轮询等待状态变化），
所以只能提示、不能据此断言模型在空转；工具的硬上限始终是 `maxToolRounds` 与 `maxToolCalls`。


## 仓库结构

插件本身零运行依赖，只用 Node 内置模块；下表之外没有构建步骤，克隆后即可运行。

| 路径 | 作用 |
| --- | --- |
| `fast-tuning.mjs` | 插件入口（`package.json` 的 `exports["./tuning"]`）：预算状态机、提示注入、工具 guard、超时改写 |
| `authorization.mjs` | 授权判定纯函数，不依赖 DSH 运行时，可单独测试 |
| `cordis.patch.yml` | bundle patch：`fast` 与 `fast-full` 两个预设、工具组成、`fast-tuning` 默认配置 |
| `*.test.mjs` | `node:test` 单元测试，由 `npm test` 汇总运行 |
| `verify-budget.mjs` | 集成检查，需要本机 `dsh`；用临时 `DSH_HOME` 跑真实提示组装与工具调度 |
| `verify-desktop.mjs` | 桌面实测的材料准备与产物检查，不替代人工记录 |
| `verification-*.json` / `verification-desktop.md` | 各期实测证据；历史文件不代表本版性能 |
| `.gitignore` | 忽略 `node_modules`、系统与编辑器文件、日志与集成临时目录 |
| `.github/workflows/ci.yml` | CI：推送 `main` 与 PR 时在 Node 22/24 上跑 `npm test` |
| `pnpm-lock.yaml` | 空 importer 的锁文件，仅声明零依赖边界，不含第三方包 |

CI 只跑单元测试。`test:integration` 依赖本机安装的 DSH 与它解析出的内部包，
无法在通用 CI 镜像中复现，仍需在装有 DSH 的机器上手动执行。

实际执行六批工具仍不受一批上限限制；用户再恢复预算，实际执行又回到一批后回答。
异常最终调用仍提供明确失败说明，不递归重试。

`verification-budget.json` 保存集成结果；`verification-budget-model.json` 保存 WorkBuddy 模型的隔离抽查。
后者使用固定模拟证据和预设服务替身，不代替桌面 GUI、真实任务或其他供应商的端到端验证。
模拟耗时不代表生产耗时，不能根据有限样本保证所有任务均更快。
1.6 版本真实模型的两次抽查使用两批、三次准入的小预算：普通请求在两步约 7.8 秒回答，
持续追查请求在三步约 10.1 秒回答。该结果只证明本次取证与回答路径正常，
不构成默认预算的生产性能或全面事实准确性证明。
1.9.x 的接口兼容性已在 DSH 0.2.0-rc.2 上验证通过：`agentPresets.composedPreset`、
`system-prompt/assemble`、`tools.guard`、`ctx.userQuestions.ask` 与工具取消接口在该版本均按预期工作。
2.0.0 未改动这些接口的用法，只调整版本号与仓库工程文件。
2026-11-05 在 DSH 0.2.0-rc.2 上重跑了这套集成检查，十九项全部通过

## 安装与更新

推荐先克隆仓库，方便后续用 Git 更新：

```bash
git clone https://github.com/lindakun/dsh-local-fast-mode.git
cd dsh-local-fast-mode
npm test
pwd
```

在 DSH 的插件管理器中添加 `link:<上一步输出的绝对路径>`，安装后新建会话并选择“快速模式”。
也可以在支持 GitHub 安装源的插件管理器中使用 `github:lindakun/dsh-local-fast-mode`；
本次实测采用本地 `link:` 安装方式。
插件须同时出现在 profile 的 `dependencies` 与 `dsh.profile.bundles` 中。
若已有内嵌的同名 `fast` 声明，先备份并移除旧声明，避免重复预设 ID。

如果桌面内置 pnpm 与已有依赖使用的 pnpm 主版本不同，可能遇到
`ERR_PNPM_UNEXPECTED_STORE`。本次安装使用与现有依赖一致的 pnpm 版本添加本地链接，
再在 profile 的 bundle 列表注册；不要为安装此插件随意切换全局 store 或升级其他插件。

本地链接安装后的更新方式：

```bash
cd <插件克隆目录>
git pull --ff-only
npm test
```

测试通过后重启 DSH，新建“快速模式”会话验证。GitHub 直接安装的副本请使用
当前 DSH 版本支持的插件更新流程；仓库推送不会自动改写已安装副本。

普通应用更新不会直接改写本目录的源码；链接与 bundle 注册均保存在用户 profile。
本地目录需要持续保留，删除、移动或重建 profile 后需要重新添加链接。
建议把克隆目录放在固定的插件目录，例如 `~/.dsh/local-plugins/dsh-local-fast-mode`，
不要放在经常清空的作品工作区内；`link:` 不会复制源码，源目录被删后插件也会失效。
DSH 仍处于预览期，升级可能改变 Cordis 接口或预设配置格式；升级后需运行测试、
重启应用并新建快速模式会话验证。此机制避免应用文件覆盖，不保证跨版本接口永远兼容。
1.3 依赖公开的 `agentPresets` 服务及 `composedPreset` 方法；升级后还应在空白会话中
从其他预设切入快速模式，确认首步提醒出现。服务依赖缺失由 Cordis 加载诊断显示，
不会退回读取可能过期的创建 header。
1.6 还依赖公开的 `system-prompt/assemble`、`tools.guard` 与工具取消接口；
升级后运行集成检查，确认工具移除、执行拒绝和回答阶段仍按预期工作。
1.8 另依赖公开的 `ctx.userQuestions.ask`；该服务缺失时自动退回纯文字识别，不影响加载。
上述接口在 0.2.0-rc.2 上的兼容性已实测通过；高版本升级后仍需重跑 `npm run test:integration`。
已有会话可能继续使用创建时的预设快照，验证配置变更应新建会话。

## 回滚

安装前请自行备份 desktop profile。首次迁移的完整回滚需在退出 DSH 后恢复备份中的 `cordis.patch.yml`、`package.json`、
`pnpm-lock.yaml` 与 `fast-tuning.mjs`，再启动应用。恢复整份 profile 会撤回备份之后的其他设置，
因此有后续配置改动时应只针对本插件移除依赖、bundle 条目并恢复旧预设声明。

后续仅回滚本插件版本可使用 Git，再重启 DSH、新建会话验证。
源码仓库不保存账号、凭据、完整 profile 或原始会话。
